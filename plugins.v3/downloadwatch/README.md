# 下载监控（DownloadWatch）

定时扫描下载器中**正在下载**的任务，把「等待时间已经很长、进度却几乎没动」的任务判定为
卡死并清理，同时记住这个种子，避免它被反复下载。

## 判定规则

两个条件同时满足才会删除：

1. **等待时长 ≥ 等待时长阈值**（小时）
2. **进度 ≤ 进度阈值**（百分比）

配套的保护：

- 只监控状态为 **正在下载**（`downloading`，含 qBittorrent 的 stalledDL / metaDL /
  checkingDL 等子状态）的任务。暂停（`paused`）与已完成（`completed`，含做种）的任务
  直接跳过，并清掉它们的观察计时，恢复下载后重新计时。
- 已完成的任务（进度 ≥ 99.9%）**永不处理**。
- 刚被插件看到、还没计时满一轮的任务不判定。
- 只监控带指定标签的任务，标签留空则监控全部任务。

> **关于"等待时长"的说明**：宿主返回的下载任务对象只包含 `hash / title / progress /
> tags / state / left_time` 等字段，**没有**任务添加时间（qBittorrent 的 `added_on`
> 没有被投影到统一模型里）。因此本插件按"首次观测到该任务的时间"开始计时。副作用是：
> 插件启用前就已经存在的任务，计时从启用后第一次扫描开始算；启用后新加的任务计时基本
> 贴合真实下载时长。

## 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 启用后才注册定时扫描服务 |
| 扫描周期 | `*/10 * * * *` | cron 表达式，默认每 10 分钟 |
| 等待时长阈值（小时） | 24 | 条件一，`≥` 判定 |
| 进度阈值（%） | 5 | 条件二，`≤` 判定 |
| 监控标签 | 空 | 逗号分隔；留空表示不过滤 |
| 同时删除文件 | 关 | 删除任务时是否连已下载内容一起删 |
| 删除后拉黑 | 开 | 种子 hash 进本地黑名单，再次出现立即删除 |
| 写入订阅排除规则 | 关 | 见下文，会修改你的订阅配置 |
| 演练模式 | 关 | 只记录将要删除的任务，不真正删除 |
| 消息通知 | 开 | 通知总开关，关闭后不推送任何消息 |
| 监控通知 | 开 | 有任务新进入监控时推送一条 |
| 删除通知 | 开 | 删除任务时推送一条 |

## 通知与详情页

两类事件会合并成**一条**通知，避免一次扫描刷两条消息：

- **【新增监控】** 本轮第一次被插件看到、且标签命中的未完成任务。每个任务只通知一次。
- **【已删除】** 本轮实际删除的任务，带进度、已等待时长、删除原因；演练模式下的命中只
  进入页面「最近一次扫描命中明细」，不会出现在删除段里。

通知是事件驱动的，不是每轮扫描都发：没有新任务、没删任务就不会打扰。标题形如
`下载监控：删除 1 个任务｜新增监控 2 个任务`，单段超过 10 条只列前 10 条并给出省略数量。

详情页顶部是四个等宽按钮，点哪个就只加载那个列表，按钮上带条目数量：

- **监控中**：正在下载、标签命中且尚未达到删除条件的任务，每行给标题与
  进度 / 已等待 / 大小 / 速度 / 标签 / 首见时间。每轮扫描整体刷新。
- **已删除**：删除时间、标题、进度、已等待、原因、文件是否一起删、订阅处理结果。
  按时间累积（上限 100 条），最新的在最上面。
- **黑名单**：被拉黑的种子标题、删除时间、原因与前 12 位 hash，最新的在最上面。
- **最近命中**：最近一次扫描的命中明细；演练模式下命中的任务只在这里出现，不会真删。

每条列表最多渲染 50 行，超出时页面底部会提示总条数。

## 删除之后，怎么让同一个种子不再被下载

这是本插件最需要说清楚的部分：MoviePilot **没有**"种子级黑名单"这个宿主配置项，
所以需要分层处理，插件提供前两层，第三层需要你自己动手。

### 第一层：本地黑名单（默认开启，最可靠）

删除任务时把种子 hash 记入插件自己的黑名单（`save_data` 持久化，上限 500 条）。
之后每一轮扫描都会检查：只要下载器里再出现这个 hash，无论是重新订阅、手动加种还是
辅种，**当轮就被删掉**。它不依赖订阅是否还存在，因此对"删了订阅再重新订阅"同样有效。

只按 hash 匹配，不按标题模糊匹配 —— 避免把同名但不同压制组的新种子误删。

### 第二层：写入订阅排除规则（可选，从源头阻止）

开启后，插件会：

1. 从任务标题解析出媒体名与季号（`Some.Show.S02E05...` → `Some.Show` / S02）；
2. 在订阅列表里找**唯一匹配**的那条订阅；
3. 把种子标题作为正则分支追加到该订阅的「排除」字段。

> 宿主的订阅「排除」字段整体是**一条正则**，多条规则用 `|` 连接，所以插件用
> `原有规则|<转义后的标题>` 的方式合并，并且做了幂等处理（重复运行不会越拼越长）。

只在能唯一定位到订阅时才写入；匹配到多条或一条都没有时只记录日志、不改配置。
订阅被删掉重建后这条规则会消失，此时靠第一层兜底。

### 第三层：手动加一条规则组排除（最彻底）

如果某个资源反复出现且 hash 每次都变（站点重新做种），可以把它的特征词
（如压制组名、字幕组标记）加进过滤规则组的排除规则。插件会在通知里列出被删种子的
完整标题，方便你复制。

## 远程命令

| 命令 | 作用 |
| --- | --- |
| `/dw_scan` | 立即扫描一次，结果以通知返回 |
| `/dw_status` | 查看插件状态、判定条件、黑名单条数与最近一次扫描结论 |

| `/api/v1/plugin/DownloadWatch/tab?tab=watched` | GET | bear | 切换详情页列表（watched / removed / blacklist / detail） |

## 已知限制

- 等待时长基于首见时间，不是下载器里的真实添加时间（原因见上）。
- 判断"卡死"只看进度与时间，不看速度；qBittorrent 的 `queuedDL` 被宿主归到
  正在下载，排队中的任务同样会被计时，建议把阈值设得比最长排队时间更大。
- 暂停的任务不参与监控，也不会被自动删除。
- `list_torrents(include_all_tags=True)` 会读取全部任务，任务量大时单轮耗时略高，
  扫描周期不建议低于 5 分钟。
- 不支持虚拟分身共享同一份黑名单以外的排他资源（如固定 webhook 名），
  多实例场景请分别配置不同的标签。
