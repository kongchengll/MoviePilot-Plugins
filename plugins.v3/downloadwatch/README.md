# 下载监控（DownloadWatch）

定时扫描下载器中**正在下载**的任务，两条规则任一命中即清理：卡死任务，以及监控满
24 小时仍未下载完成的任务（默认连本地文件一起删）。删除后记住这个种子并回滚订阅进度，
避免它被反复下载、或让订阅误以为这一集已经下过。

## 判定规则

两条规则**任一命中**即删除，判定时先看规则二。

### 规则一：卡死清理

两个条件同时满足：

1. **等待时长 ≥ 等待时长阈值**（小时）
2. **进度 ≤ 进度阈值**（百分比）

### 规则二：满 24H 强制清理（默认开启）

任务从插件首次监控起**满 24 小时仍未下载完成**，就直接删除下载任务，默认**连本地已
下载文件一起删**。这条规则不看进度：哪怕任务一直在缓慢前进、进度已经 80%，只要 24 小时
没下完就清掉，避免慢种长期占着下载位。

- 时长可用「强制清理时长（小时）」调整，默认 24；填 0 会回落到 1 小时，防止误清空。
- 「强制清理时删除本地文件」是这条规则**独立**的开关，默认开，不受上方「同时删除文件」
  影响；反过来普通卡死清理也不受它影响。删除文件不可恢复。
- 演练模式下只记录不删除，明细里会写明本来会连文件一起删。
- 命中后同样会拉黑种子、回滚订阅进度并推送删除通知，明细与「已删除」列表里原因显示为
  「满时限未完成（强制清理）」。

> ⚠️ **升级后建议先开一轮演练模式**：计时用的是插件已持久化的「首次观测时间」，升级前
> 就已经挂了超过 24 小时的任务，会在升级后第一轮扫描直接命中这条规则并删文件。先到
> 「最近命中」分页核对清单，确认没有想留的任务，再关掉演练模式。

两条规则共同的保护：

- 只监控状态为 **正在下载**（`downloading`，含 qBittorrent 的 stalledDL / metaDL /
  checkingDL 等子状态）的任务。暂停（`paused`）与已完成（`completed`，含做种）的任务
  直接跳过，并清掉它们的观察计时，恢复下载后重新计时。
- 已完成的任务（进度 ≥ 99.9%）**永不处理**。
- 刚被插件看到、还没计时满一轮的任务不判定。
- 只监控带指定标签的任务，标签留空则监控全部任务；**规则二同样受标签约束**。

> **关于"等待时长"的说明**：宿主返回的下载任务对象只包含 `hash / title / progress /
> tags / state / left_time` 等字段，**没有**任务添加时间（qBittorrent 的 `added_on`
> 没有被投影到统一模型里）。因此本插件按"首次观测到该任务的时间"开始计时。副作用是：
> 插件启用前就已经存在的任务，计时从启用后第一次扫描开始算；启用后新加的任务计时基本
> 贴合真实下载时长。

## 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 启用后才注册定时扫描服务 |
| 扫描周期 | `*/10 * * * *` | cron 表达式，默认每 10 分钟 |
| 等待时长阈值（小时） | 24 | 规则一条件一，`≥` 判定 |
| 进度阈值（%） | 5 | 规则一条件二，`≤` 判定 |
| 满 24H 强制清理 | 开 | 规则二总开关：监控满时限仍未完成就直接删任务 |
| 强制清理时长（小时） | 24 | 规则二的时限，从首次监控开始计时 |
| 强制清理时删除本地文件 | 开 | 只作用于规则二，删任务时连已下载文件一起删，不可恢复 |
| 监控标签 | 空 | 逗号分隔；留空表示不过滤，两条规则都受它约束 |
| 同时删除文件 | 关 | 只作用于规则一，删除任务时是否连已下载内容一起删 |
| 删除后拉黑 | 开 | 种子 hash 进本地黑名单，再次出现立即删除 |
| 写入订阅排除规则 | 关 | 可选，会把整条种子标题写进订阅排除正则，同一标题的其它版本也会被排除 |
| 演练模式 | 关 | 只记录将要删除的任务，不真正删除 |
| 消息通知 | 开 | 通知总开关，关闭后不推送任何消息 |
| 监控通知 | 开 | 有任务新进入监控时推送一条 |
| 删除通知 | 开 | 删除任务时推送一条 |

> **删除任务一定会回滚订阅进度**，这一行为没有开关：不回滚的话宿主会认为该集已下载，
> 订阅再也不会重新搜索它。详见下文「删除之后」。

## 通知与详情页

两类事件会合并成**一条**通知，避免一次扫描刷两条消息：

- **【新增监控】** 本轮第一次被插件看到、且标签命中的未完成任务。每个任务只通知一次。
- **【已删除】** 本轮实际删除的任务，带进度、已等待时长、删除原因；命中规则二时会额外
  标注「满时限未完成，强制清理 · 连本地文件一起删」。演练模式下的命中只进入页面
  「最近一次扫描命中明细」，不会出现在删除段里。

两种删除规则的「是否连文件删」互不影响；一轮里同时出现时，通知会说明删除文件是按规则
区分的，不会笼统写成「是」或「否」。

通知是事件驱动的，不是每轮扫描都发：没有新任务、没删任务就不会打扰。标题形如
`下载监控：删除 1 个任务｜新增监控 2 个任务`，单段超过 10 条只列前 10 条并给出省略数量。

详情页自上而下分为三层：

1. **运行配置卡**：左边是标题与「已启用 / 未启用」状态标签，右边是最近扫描时间；
   下面把两个阈值、满 24H 强制清理（开/关、是否连文件删）、监控标签、扫描周期、删除
   文件、演练、拉黑、通知等参数拆成一枚枚小标签，不再挤成一整段长文本；强制清理标签
   用红色边框突出，卡片底部是一行浅色说明。
2. **四个等宽的分页按钮**：统一的圆角与高度，上行「圆点 + 名称」、下行大号条目数，
   选中项整块高亮。点哪个就只加载那个列表。
3. **记录列表**：每条是一张细边框卡片，左侧是状态徽标（监 / 删 / 禁 / 记），中间是
   单独成行的标题，下面把进度、已等待、大小、速度、标签等信息拆成小标签；前两项用
   实心色调强调，其余用细边框降噪。标题再长也不会把明细挤到同一行。

四个分页的内容：

- **监控中**：正在下载、标签命中且尚未达到删除条件的任务。每轮扫描整体刷新。
- **已删除**：删除时间、进度、已等待、原因（卡死 / 满时限强制清理 / 命中黑名单）、
  文件是否一起删、订阅处理结果。按时间累积（上限 100 条），最新的在最上面。
- **黑名单**：删除时间、原因、前 12 位 hash 与下载器，最新的在最上面。
  每条右侧有「移除」按钮，见下文「黑名单怎么改」。
- **最近命中**：最近一次扫描的命中明细；演练模式下命中的任务只在这里出现，不会真删。

每条列表最多渲染 50 行，超出时列表底部会提示总条数；空列表会显示居中的空状态说明。
页面不用任何图标字体，全部用主题色、圆角色块和文字徽标构成，明暗主题都能自适应。

### 黑名单怎么改

黑名单是按种子 hash 记的，所以误拉黑、或者某个资源换了更好的版本想重新下载时，
不需要去改插件数据文件：

- 在详情页点「黑名单」分页，每条记录右侧有「移除」按钮，点一下就删掉这一条；
- 移除只影响插件自己的黑名单，不会动下载器里的任务，也不会动订阅配置；
- 移除后该 hash 不再被当轮秒删。如果这个种子还在下载器里（比如你重置了拉黑判断又
  重新加了种），下一轮扫描会按等待时长与进度阈值重新评估，仍不达标就会再次被删并重新
  进黑名单。

接口是 `GET /api/v1/plugin/DownloadWatch/blacklist/remove?hash=<hash>`，返回三段式响应，
`data` 里带 `removed`（本次移除条数）与 `blacklist`（剩余条数）。hash 大小写不敏感；
只有拿不到 hash 的旧记录才会退回按标题全等匹配。


## 删除之后，怎么让同一个种子不再被下载

这是本插件最需要说清楚的部分：MoviePilot **没有**"种子级黑名单"这个宿主配置项，
所以需要分层处理，插件默认做前两层，第三层可选，第四层需要你自己动手。

### 第一层：回滚订阅已下载进度（默认开启，必须先有这一层）

MoviePilot 在**把种子提交给下载器的那一刻**，就已经把这一集写进了订阅的
「已下载集数」（订阅详情里的 `note`，洗版订阅还会写 `episode_priority`）。所以只把下载
任务删掉，订阅依然认为这一集已经下过 —— 表现就是"这一集再也不去搜新种子了，直接跳过"。
在订阅详情里手动清空进度之前，删多少次任务都没用。

插件删除任务后会立刻做这件事：

1. 用任务 hash 查宿主的下载历史，拿到它属于哪个媒体（`media_source` + `media_id`）、
   哪一季、覆盖哪几集；
2. 在订阅里按媒体标识定位，季号能区分时只处理同季订阅；
3. 从 `note` 里删掉这些集，`episode_priority` 里对应的键也一并删掉；
4. 删除这条下载历史，避免订阅详情继续把该集显示成"已下载文件"。

这样下一轮订阅搜索会重新把这一集当成缺失集去搜，**换下一个候选种子**。
只有能唯一定位到订阅时才动手，匹配到多条时只记录日志、不改配置。

### 第二层：本地黑名单（默认开启，最可靠）

删除任务时把种子 hash 记入插件自己的黑名单（`save_data` 持久化，上限 500 条）。
之后每一轮扫描都会检查：只要下载器里再出现这个 hash，无论是重新订阅、手动加种还是
辅种，**当轮就被删掉**。它不依赖订阅是否还存在，因此对"删了订阅再重新订阅"同样有效。

只按 hash 匹配，不按标题模糊匹配 —— 避免把同名但不同压制组的新种子误删。

黑名单不是只进不出的：详情页「黑名单」分页里每条都有「移除」按钮，误拉黑可直接删掉。

### 第三层：写入订阅排除规则（可选，默认关闭，有副作用）

开启后，插件会用下载历史定位订阅，把**整条种子标题**作为正则分支追加到该订阅的
「排除」字段（`原有规则|<转义后的标题>`，幂等，不会越拼越长）。

> ⚠️ 副作用：宿主的排除规则只匹配标题，所以**同一标题的所有种子都会被排除** ——
> 包括其它站点上的同版本种子。如果这部剧只有这一个版本，排除之后这一集就真的再也
> 下不到了，看起来就像"订阅放弃了这个剧"。只有当你确认该资源还有别的版本可下时，
> 才值得开启。

### 第四层：手动加一条规则组排除（最彻底）

如果某个资源反复出现且 hash 每次都变（站点重新做种），可以把它的特征词
（如压制组名、字幕组标记）加进过滤规则组的排除规则。插件会在通知里列出被删种子的
完整标题，方便你复制。

## 远程命令

| 命令 | 作用 |
| --- | --- |
| `/dw_scan` | 立即扫描一次，结果以通知返回 |
| `/dw_status` | 查看插件状态、两条判定条件（含满 24H 强制清理是否连文件删）、黑名单条数与最近一次扫描结论 |

## 接口

| 路径 | 方法 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `/api/v1/plugin/DownloadWatch/scan_now` | POST | bear | 立即扫描，返回本轮统计与明细 |
| `/api/v1/plugin/DownloadWatch/status` | GET | bear | 当前配置、黑名单条数、最近扫描时间 |
| `/api/v1/plugin/DownloadWatch/tab?tab=watched` | GET | bear | 切换详情页列表（watched / removed / blacklist / detail），返回 `{"success","message","data"}` 三段式响应 |
| `/api/v1/plugin/DownloadWatch/blacklist/remove?hash=<hash>` | GET | bear | 从本地黑名单移除一条记录，`data` 返回 `removed` 与剩余 `blacklist` 条数；hash 缺失时可用 `title` 兜底 |

## 已知限制

- 等待时长基于首见时间，不是下载器里的真实添加时间（原因见上）；规则二也按这个口径
  计时，所以插件刚启用时，已挂了很久的任务可能要等一轮才被看到、也可能在启用后
  立刻满时限。
- 判断"卡死"只看进度与时间，不看速度；qBittorrent 的 `queuedDL` 被宿主归到
  正在下载，排队中的任务同样会被计时，规则二也会清理排队超过 24 小时的任务。
  建议把阈值设得比最长排队时间更大，或给这类任务打上不在监控范围内的标签。
- 暂停的任务不参与监控，也不会被自动删除。
- `list_torrents(include_all_tags=True)` 会读取全部任务，任务量大时单轮耗时略高，
  扫描周期不建议低于 5 分钟。
- 不支持虚拟分身共享同一份黑名单以外的排他资源（如固定 webhook 名），
  多实例场景请分别配置不同的标签。
