# 每日入库速报（DailyEpisodeDigest）

定时统计 MoviePilot 每天新入库的剧集与电影，把每部作品的封面、标题、季集与入库时间
**渲染成一张日报长图**，再通过 MoviePilot 自身的通知渠道推送。

## 效果

图片宽度固定 1080，高度随部数增长：

```
┌──────────────────────────────────────────────┐
│  每日入库速报                        10月23日 │
│  ────────────────────────────────────────    │
│  3 部剧集 · 6 集 · 1 部电影                    │
│                                              │
│  [海报]  葬送的芙莉莲                          │
│          S01 E28 · 1 集                       │
│          入库 10-23 23:02                     │
│  ────────────────────────────────────────    │
│  [海报]  灵笼 第二季                           │
│          S02 E03-E04 · 2 集                   │
│          入库 10-23 22:15                     │
│  ...                                         │
│                        MoviePilot · 自动整理入库│
└──────────────────────────────────────────────┘
```

通知正文只保留一句概要（`共 3 部剧集 · 6 集 · 1 部电影`），作为不支持图片渠道的兜底文案。

## 数据来源

统计口径是宿主 **整理入库记录**（`TransferHistory`），通过稳定 SDK
`app.sdk.queries.list_transfer_history` 读取，不直接访问宿主 ORM。

因此：

- 由 MoviePilot 整理入库的内容会被统计。
- 手工直接拷进媒体库、未经 MoviePilot 整理的文件不会被统计。
- 同一部剧同一季的多条记录（洗版、分批整理）会按「标题 + 季」合并，集号去重。

## 配置项

| 配置 | 说明 |
| --- | --- |
| 启用插件 | 总开关，关闭时不注册定时服务 |
| 推送周期 | 5 位 cron，默认 `0 9 * * *`（每天 9 点） |
| 统计范围 | 昨日 00:00-24:00 / 今日 00:00-当前 / 最近 24 小时 |
| 统计类型 | 电视剧、电影，可多选 |
| 图片内最多列出部数 | 1-20，默认 8；超出部分在图片底部提示「另有 N 部未列出」 |
| 排除关键词 | 逗号分隔，命中标题即跳过（如 `特辑,预告`） |
| 外网访问地址 | 图片需要通知渠道能访问到本机；留空则用 MoviePilot 设置中的外网访问地址 |
| 中文字体路径 | 留空则自动查找或下载 |
| 无新增也推送 | 关闭时无入库静默跳过 |
| 保存后立即推送一次 | 用于验证效果，触发后自动复位 |

## 手动触发

插件启用后会注册远程命令，在任意已绑定的消息渠道（Telegram、微信、钉钉等）发送即可：

```text
/digest_push            按配置的统计范围推一次
/digest_push today      临时按「今日 00:00 - 当前」推一次
/digest_push 24h        临时按「最近 24 小时」推一次
```

触发后会给发起人回一条执行结果（`已推送 3 部 / 6 集（含图片）`），
连续触发有 60 秒冷却，避免刷屏。命令不影响定时服务，也不会改动配置。

命令的实现路径：`get_command()` 声明 `/digest_push` 并绑定 `EventType.PluginAction`，
再通过 `@eventmanager.register(EventType.PluginAction)` 按 `action` 判定归属。

## 图片怎么送到通知渠道

MoviePilot 的通知消息只接受 **一个图片 URL**，由各渠道服务端自行下载。因此插件：

1. 生成图片存到插件数据目录 `digest_<日期>_<时间>.jpg`，只保留最近 10 张。
2. 通过匿名接口 `GET /api/v1/plugin/DailyEpisodeDigest/card/<文件名>` 暴露。
   入参用文件名白名单校验，只可能读到本插件生成的图片。
3. 把该接口的完整地址填进通知的 `image` 字段。

**这要求通知渠道能访问到你的 MoviePilot**，所以必须配置可公网访问的地址
（MoviePilot 设置里的「外网访问地址」，或在插件里单独填）。地址为空、是
`localhost` / `127.x` / `10.x` / `192.168.x` / `172.16-18.x` 时视为不可用，
本次推送自动降级为纯文本（完整清单）。

## 中文字体

MoviePilot 官方镜像**没有安装任何中文字体**，Pillow 内置字体也不含 CJK 字形，
直接画中文会全是方块。插件按以下顺序找字体，前一个可用即用：

1. 配置项「中文字体路径」
2. 插件目录 `fonts/` 下你自行放入的 `.otf/.ttf/.ttc`
3. 插件数据目录 `fonts/` 下的缓存
4. 宿主系统的常见中文字体路径
5. 从 jsDelivr / GitHub 下载 Noto Sans CJK SC（约 16MB，仅首次），缓存到插件数据目录

全部失败时记录错误并降级为纯文本推送。离线部署建议直接把字体放到插件目录 `fonts/` 下。

## 实现约定

- 只从 `app.sdk.*` 导入，不使用 `app.core.*` / `app.helper.*` / `app.utils.*` /
  `app.db.models.*`。
- `init_plugin()` 先调用 `stop_service()`，可被宿主重复调用。
- 一次性任务走 `app.sdk.scheduler.add_plugin_once_job`，不自建调度器。
- 取数失败、出图失败、通知发送失败都只影响当次推送，不抛出到宿主。
- 运行数据与图片写在插件数据目录，不写回源码目录。

## 目录结构

```text
plugins.v3/dailyepisodedigest/
├── __init__.py    # 插件类：生命周期、表单、定时服务、图片接口
├── config.py      # 默认配置、规范化、统计窗口计算
├── collector.py   # 经 SDK 读取整理历史
├── digest.py      # 聚合与纯文本兜底渲染（纯标准库，可脱离宿主测试）
├── fonts.py       # 中文字体解析、下载与缓存
├── card.py        # 日报长图绘制
└── README.md
```

## 测试

`digest.py` 与 `config.py` 不依赖宿主，可直接测试；测试放在 `tests/v3/dailyepisodedigest/`，
按宿主约定使用生产命名空间导入：

```bash
../MoviePilot/.venv/bin/python -m pytest tests/v3/dailyepisodedigest
```
